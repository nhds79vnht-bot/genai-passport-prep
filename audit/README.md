# AIパスポート品質監査：永続化・再開手順

## 唯一の進捗基準
- 第1章: `audit/chapter1-progress.json`。チャット内の進捗報告ではなく、GitHubの保存済み台帳を優先する。
- 現在の問題本文は `src/data/` 配下6ファイルから取得する。修正済み本文を最初から書き直さない。
- 台帳の `unverified` は「検証証跡が未登録」であり「作業実績ゼロ」ではない。
- チャット停止後は、まず台帳と6ファイルを再取得して再開する。以前のチャットに確認を求めない。

## 問題別ステータス
- `unverified`: 完了を証明する監査記録がない。
- `needs_fix`: 具体的な品質違反を発見。必ず `findings` に根拠を記録する。
- `recheck`: 修正済みだが、修正後の正答・選択肢・解説の検証が未完了。
- `passed`: 現行の問題本文に対して合格基準を検証済み。`verified_at_commit` を保存する。
- 問題本文を変更したら、その問題の `passed` は無効とし `recheck` に戻す。
- 他の問題の変更によって意味的重複が生じた場合も、影響を受ける問題を再検査する。

## 保存プロトコル
1. GitHubの最新の問題ファイルと台帳を取得し、問題IDを照合する。問題数300、ID重複0を維持。
2. 原則100問を目標に、対象ID・シラバス中小項目・難易度・正答妥当性・誤答選択肢・解説・重複を確認する。
3. 問題の修正をGitHubへ保存する。保存に成功した問題は、台帳では `recheck` とする。
4. 修正後のGitHub本文を再取得し、必要な検証を終えた問題のみ `passed` にする。
5. **台帳更新をGitHubにコミットし、その保存を確認する。** `checkpoint` の集計・最終処理ID・次の作業・参照コミットを更新する。
6. 問題ファイルの保存後に台帳保存前で停止した場合、次回は差分と最新本文を照合し、未反映の台帳を復旧する。保存済みの修正を破棄しない。
7. 台帳と問題ファイルのGitHub更新は別コミットになり得る。完全な原子性を保証できないため、再開時に必ず最新コミットとの整合性を確認する。

## 第1章の終了判定
- 全300問の公式2027年版シラバス小項目への分類が完了、範囲外0。
- 中項目分布: 1-1=45、1-2=75、1-3=115、1-4=65。
- 正答なし・意図しない複数正答・解説矛盾・実質重複が0。
- 明らかに捨てられる誤答が2個以上の問題が0。
- 難易度目標: 基礎90、標準150、応用60（公式比率ではなく設計目標）。
- 第1巡の是正後、**第2巡で300問全件を再監査**し、阻害事項0で初めて `chapter_accepted=true`。
- 合格まで第2章の修正を始めない。合格したら第2章のシラバス確定→300問抽出→小項目分類→分布分析→品質監査→不足分野への再配分→全件再監査の順で進む。

## 次の作業位置
`checkpoint.phase`、`checkpoint.last_completed_id`、`checkpoint.next_action` を読む。進捗件数は `items[].status` から再計算し、集計と一致しなければ修正する。実測できない項目を推測で埋めない。

GitHub Actionsは使用しない。少数問ごとの承認・報告で停止しない。
